\section{FlySearch: Exploring how vision-language models explore}
\label{sec:flysearch}

\subsection{Motivation}
\label{sec:flysearch-motivation}

Despite the rapid development of vision-language models as zero-shot tools across a wide range of perception and reasoning tasks, their ability to perform goal-directed exploration in open three-dimensional environments has received little systematic attention. The existing benchmarks that come closest each fall short of the goal as shown in Section~\ref{sec:openworld-scope}. FlySearch addresses these gaps directly -- it provides a simulated photorealistic outdoor environment with a three-dimensional action space, a zero-shot language-conditioned search task, and a suite of standardised challenges that isolate distinct aspects of exploration capability. By evaluating VLMs directly rather than as components within a larger navigation system, it measures spatial exploration capability in isolation.

\subsection{Benchmark design}
\label{sec:flysearch-benchmark}

\textbf{Task formulation.} In \flysearch{}, the agent controls a simulated multirotor UAV equipped with a downward-facing camera. The UAV serves as a proxy for evaluation of spatial exploration capability, rather than low-level control of a physical robot, and is therefore controllable with high-level relative movement commands, resembling autopilot inputs. The agent is tasked with finding a target object described in natural language or with a visual example. The interaction follows a fixed protocol designed to be equally natural for human testers and VLMs, outlined in Figure~\ref{fig:flysearch-teaser}.

At the start of each episode, the model receives a \emph{starting prompt} that contains a brief textual description of the object to be located (e.g.\ \emph{a red pickup truck}) and in some cases a visual example of the target object. The starting prompt also specifies the communication format, and an instruction that the model may preface each response with a chain of reasoning before issuing its action. This allows the model to ``think aloud'' before committing to a movement~\cite{wei2022chain}.

At each subsequent step, the agent receives an \emph{observation} consisting of a $500\times500$ pixel RGB image from the UAV camera, overlaid with a coordinate grid~\cite{lei2024scaffolding} to help the model judge distances and directions, together with the current altitude above the ground.

The agent responds with an \emph{action}: a text command \texttt{<action>(X, Y, Z)</action>} specifying a relative displacement in metres in the three spatial directions, or the terminal command \texttt{FOUND} when it believes the target is in view. Low-level flight control (collision avoidance, trajectory execution) is handled by a simulated autopilot layer, so the model focuses entirely on exploration decisions.

An episode is considered successful if, at the moment the agent issues \texttt{FOUND}, the object's centre point lies within the camera's field of view \emph{and} the agent is at most $10\,\mathrm{m}$ above the object's highest point. This metric, adapted from the standard ObjectNav criterion~\cite{batra2020objectnav}, requires the agent to be close enough for meaningful visual confirmation rather than merely in the neighbourhood of the target.

\textbf{Evaluation pipeline.} The \flysearch{} system, shown in Figure~\ref{fig:flysearch-pipeline}, consists of three main components: a simulator, an evaluation controller, and a scenario generator. The \emph{simulator} is built on Unreal Engine 5~\cite{unrealengine}, which provides near-photorealistic graphics through real-time ray tracing and dynamic global illumination. Large, open-world maps are supported natively, and the procedural content generation system can place tens of thousands of object meshes in seconds at runtime, enabling an unlimited number of distinct evaluation scenarios. The \emph{evaluation controller} is implemented in Python and handles the full lifecycle of the benchmarking process: managing the communication between the simulator and the VLM under test, enforcing episode termination conditions, and computing performance metrics. The controller supports a wide range of VLMs through a simple adapter interface, and additional models can be integrated using the open-source vLLM inference server~\cite{kwon2023efficient}. The \emph{scenario generator}, functionally integrated with the other two components, procedurally generates new evaluation scenarios: it builds the forest map entirely at runtime and spawns the distractor assets of the city environment, so that no two scenarios share the same layout.

\textbf{Environments.} The benchmark provides two distinct evaluation environments. The \emph{forest environment} is based on the Electric Dreams UE5 demo~\cite{electridreams} and features sparse forest scenery with randomly placed rock formations, procedurally generated vegetation, and dynamic wind. The entire map is generated at runtime, ensuring that no two scenarios share the same layout. The \emph{city environment} is based on the City Sample UE5 demo~\cite{citysample}, a large, semi-procedurally generated American-style city of approximately $4\times4\,\mathrm{km}$, populated at runtime with random distractor assets (parked cars, walking pedestrians) drawn from Unreal's asset marketplace. The visual complexity of the city environment is substantially higher than the forest, with many objects of similar appearance and strong visual clutter. Figure~\ref{fig:flysearch-environments} shows example scenes from both environments.

\textbf{Scenario sets.} In addition to the procedurally generated environments, three standardised challenge sets are defined, each designed to stress a different aspect of exploration. To ensure reproducibility, the scenarios in those sets are pre-generated to ensure all models are evaluated in the same conditions.

\textbf{\challenge{}} contains 400 scenes across forest and city environments. The agent has at most 10 actions to find the target object. The starting altitude is between 30 and 100~m, the search area is bounded to $400\times400\times120\,\mathrm{m}$, and crucially, the target is always within the camera's field of view at the starting position (though it may be too small to identify from above). This setting tests basic perception, spatial reasoning, and short-horizon navigation. City targets include road construction works, crowds, large trash piles, fires, and vehicles of specified types and colours; forest targets include campsites, trash piles, persons, forest fires, and buildings.

\textbf{\anomalychallenge{}} contains 200 scenes using the same setup as \challenge{} but with a twist: the agent must find an object that does not belong in its environment (for example, a giraffe wandering through a city or a flying saucer in a forest) without being told which specific object is out of place. The agent must first determine what constitutes an anomaly and then locate it. This tests contextual world knowledge on top of basic search capability.

\textbf{\hardchallenge{}} contains 200 harder city scenes in which the starting altitude is raised to 100--125~m and dynamic lighting simulates different times of day. Most importantly, the target object may be completely outside the initial field of view. The agent may also move beyond its current field of view at each step. This setting requires the agent to form and execute a systematic multi-step search strategy, exploring the environment methodically until the target is found.

\subsection{Experimental results}
\label{sec:flysearch-results}

\textbf{Models evaluated.} Ten VLMs are benchmarked across the three challenge sets. Three proprietary models are included: GPT-4o~\cite{achiam2023gpt}, Claude 3.5 Sonnet~\cite{Anthropic_2024}, and Gemini 2.0 Flash~\cite{Google_2024}. Three large open-weight models (above 11B parameters) are evaluated: Qwen2-VL-72B~\cite{Qwen2VL}, Llava-Onevision-72B~\cite{li2024llavaonevisioneasyvisualtask}, and Pixtral-Large-124B~\cite{Mistral_2025}. Four small open-weight models (below 11B parameters) round out the evaluation: Phi-3.5-vision~\cite{abdin2024phi3technicalreporthighly}, InternVL2.5-8B-MPO~\cite{wang2024enhancingreasoningabilitymultimodal}, Llava-Interleave-7B~\cite{li2024llavanextinterleavetacklingmultiimagevideo}, and Qwen2.5-VL-7B~\cite{bai2025qwen2}. Human baselines are collected via an online study, comprising 111 recorded episodes for \challenge{} City and 51 for \hardchallenge{}.

\textbf{\challenge{} results.} Table~\ref{tab:flysearch-main-results} reports success rates for \challenge{} and \hardchallenge{}. On \challenge{}, the best-performing model is Gemini 2.0 Flash at 42.0\%, closely followed by Claude 3.5 Sonnet at 41.2\% and GPT-4o at 39.5\%. Human participants, evaluated on the city environment, achieve 66.7\%, approximately 25 percentage points above the best VLM on the same split. Among large open-weight models, Pixtral-Large performs best at 29.8\%, with Qwen2-VL-72B at 17.2\% and Llava-Onevision-72B at 9.5\%. The small open-weight models essentially fail, with no model exceeding 4\%. Investigation reveals that small models largely fail to follow the instruction format, often neglecting to issue the \texttt{FOUND} command even when the target is within view at the end of an episode.

\textbf{\hardchallenge{} and the exploration gap.} The most striking result concerns \hardchallenge{}. Human participants score 60.8\% (a modest drop from their \challenge{} City score of 66.7\%), reflecting that systematic search is a natural cognitive strategy that humans execute reliably when given sufficient steps. VLMs collapse dramatically. The best-performing model on \hardchallenge{} is Claude 3.5 Sonnet at just 6.5\%, and GPT-4o and Gemini achieve 3.5\% and 6.0\% respectively. The relative gap between the best VLM and humans grows from roughly 60\% on \challenge{} to more than 800\% on \hardchallenge{}.

This collapse cannot be attributed solely to the harder detection conditions. The core problem is that \hardchallenge{} requires a genuine search strategy, covering the environment systematically and tracking which areas have been visited. Human participants intuitively begin following streets, grid-scanning districts, and ascending to survey larger areas when uncertain. VLMs, by contrast, tend to move in inconsistent, locally reactive patterns, often repeating previously visited regions, failing to track coverage, and being easily derailed when they lose sight of a candidate object. This behavioural gap is further exacerbated by context-length degradation -- models given 20 steps instead of 10 score lower, which was isolated in an ablation study.

\textbf{Qualitative analysis.} Manual inspection of failure trajectories reveals consistent failure modes across all models. When a model loses sight of an object it was tracking, it often backtracks or begins hallucinating the object's presence at an incorrect location, rather than reasoning about where the object was last seen and moving towards it. Collision handling is universally poor, with all models occasionally attempting to repeat an action that was rejected by the collision avoidance system, rather than navigating around the obstacle. In several recorded trajectories, Gemini 2.0 Flash abandons the task entirely after a collision, noting ``I am unable to navigate without hitting the building.'' Figure~\ref{fig:flysearch-trajectory} shows an example of a successful trajectory, illustrating the descent-and-approach strategy that works well on \challenge{} but is insufficient when the target is not visible from the starting position in \hardchallenge{}.

\textbf{\anomalychallenge{} results.} Table~\ref{tab:flysearch-anomaly} shows results on \anomalychallenge{}. Scores are substantially lower than on \challenge{}: the best model, Gemini 2.0 Flash, achieves only 35.5\% overall, compared with 42.0\% on \challenge{}, and performance is notably weaker in the city than in the forest. The gap reflects an additional challenge beyond search: the agent must first determine \emph{which} object in the scene is out of place before it can locate it. VLMs consistently misjudge this determination, often flagging visually distinctive but contextually normal objects (a yellow taxi in a city scene) while ignoring semantically obvious anomalies (a tank standing next to it). Naming the anomaly object explicitly, eliminating the need for contextual judgement, raises Gemini's score from 35.5\% to 46.5\%, confirming that the primary bottleneck is semantic reasoning rather than visual search.

\textbf{Fine-tuning analysis.} To investigate whether fine-tuning can close the gap, Qwen2.5-VL-7B is fine-tuned using the GRPO algorithm~\cite{shao2024deepseekmath} on a set of 67,500 synthetically generated training examples derived from flight trajectories in the Forest environment. The reward function incentivises the model to move closer to the target at each step, produce explicit reasoning, and correctly issue \texttt{FOUND} when the target is in view. Training is conducted in offline, step-wise mode using LoRA~\cite{hu2022lora} on four H100 GPUs.

The resulting fine-tuned model is evaluated on both the Forest environment it was trained on (achieving 57.0\% on \challenge{} Forest) and the held-out City environment (achieving 27.0\% on \challenge{} City). The transfer to City is notable: the base model scored only 1.5\%, so the improvement shows that fine-tuning taught transferable spatial reasoning skills rather than memorising environment-specific features. However, on \hardchallenge{}, the fine-tuned model scores 0.0\%, identical to the base model. The fine-tuning addresses surface-level failures (instruction format adherence, short-horizon spatial manoeuvring) but does not instil the systematic multi-step coverage strategy that \hardchallenge{} requires, suggesting that the exploration gap is a deeper limitation of current models rather than an artefact of missing task-specific training.

Additional experimental results are provided in the paper~\pubcite{pardyl2025flysearch}.

\subsection{Contributions}
\label{sec:contributions-flysearch}

The publication ``FlySearch: Exploring how vision-language models explore''~\pubcite{pardyl2025flysearch} makes the following contributions to the field:

\begin{itemize}
    \item It introduces two high-fidelity photorealistic outdoor evaluation environments, a procedurally generated forest and a large semi-procedural city, both built with Unreal Engine 5 and capable of generating an unlimited number of reproducible scenarios with diverse conditions (time of day, object placement, distractor density).
    \item It defines three standardised benchmark challenge sets (\challenge{}, \anomalychallenge{}, \hardchallenge{}) with increasing difficulty, designed to isolate distinct aspects of exploration capability: basic object detection and short-horizon navigation, contextual anomaly identification, and systematic multi-step coverage of an area in which the target is not initially visible.
    \item It provides an evaluation of ten VLMs across all three challenges, with human baselines, revealing consistent failure modes (hallucination when losing a target, inability to plan systematic coverage, sensitivity to long contexts) shared across proprietary and open-weight models alike.
    \item It demonstrates through GRPO fine-tuning that surface-level failures (instruction following, spatial grounding) are correctable with synthetic data, but that the deeper inability to form and execute multi-step exploration strategies persists after fine-tuning, identifying this as an open problem for current VLMs.
\end{itemize}

FlySearch makes the problem of open-world exploration precise. By characterising where current models fail and under what conditions the gap to human performance is largest, it establishes a concrete set of open problems and a reproducible benchmark against which future progress can be measured.
